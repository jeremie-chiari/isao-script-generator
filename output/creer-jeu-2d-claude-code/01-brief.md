## Contexte Cible (extrait des briefs)

**Persona principal** : L'Idéateur (25-45 ans) — diplômé école de commerce, idée d'app/SaaS, bute sur le mur technique, budget dev quasi nul. Et le Freelance Autonome (28-45 ans) — consultant, coach, marketeur, dépendant des prestataires tech.

**Frustration fondamentale** : "J'ai l'idée, mais pas les mains pour la construire."

**Points de douleur activés par cette vidéo** :
- Dépendance technique — "je ne sais pas coder, donc je ne peux pas créer"
- Complexe de l'imposteur — "c'est pas pour moi, c'est pour les devs"
- FOBO — peur d'être dépassé par l'IA au lieu de l'utiliser

**Croyances à désamorcer** :
- "Le code est pour les geeks/ingénieurs" → Un jeu créé en 10 min sans taper une ligne de code
- "C'est trop tard pour moi" → Zéro prérequis technique démontré en live

**Ton** : Direct, factuel, sobre, anti-gourou. Comme un collègue compétent qui montre ce qu'il a fait.

**Communauté Skool** : https://www.skool.com/isao-1009/about — le CTA naturel serait d'inviter à rejoindre la communauté pour poser des questions et partager ses créations.

## Notes complémentaires

- **Environnement** : Antigravity IDE (l'IDE de Google avec Claude Code intégré) — interface visuelle, plus accessible qu'un terminal brut pour le public non-technique
- Le jeu est un jeu 2D basique (type space shooter) — visuellement parlant avec couleurs néon
- L'angle "0 compétence technique" est central : le viewer doit se dire "si lui peut le faire, je peux le faire"
- **Deux vrais secrets révélés dans la vidéo** :
  1. Le fichier CLAUDE.md — briefer Claude Code sur le projet avant de coder (comme briefer un collègue)
  2. La technique du "prompt visuel" — décrire ce qu'on VOIT à l'écran, pas ce qu'on VEUT obtenir
- Le process montré = le CLAUDE.md, les prompts utilisés, la logique de demande, comment itérer avec Claude Code
- Le guide promis en fin de vidéo = levier de rétention (annoncé en intro, livré en outro)
